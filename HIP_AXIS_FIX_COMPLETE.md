# Hip Axis Inversion Fix - Complete Solution

## Problem Summary

The Humanoid SNC R5 robot had **asymmetric walking behavior**:
- ✗ Right leg stepped forward correctly
- ✗ Left leg stepped BACKWARD (or stayed behind)
- ✗ Robot could not learn to walk despite using G1's proven configuration

## Root Cause

**Hip pitch axis directions are inverted in the URDF:**

```xml
<!-- LEFT hip (WRONG direction) -->
<axis xyz="0.006, -0.9999, 0" />

<!-- RIGHT hip (correct direction) -->
<axis xyz="-0.006, 0.9999, 0" />
```

When the RL policy sends the same action value to both hips:
- Right hip rotates FORWARD → leg steps forward ✓
- Left hip rotates BACKWARD → leg steps backward ✗

This makes symmetric walking **impossible** to learn.

## Solution: Action Scale Dictionary

Instead of regenerating the USD file from fixed URDF (which didn't work), we use Isaac Lab's **built-in action scale feature** to invert the left hip action.

### Files Modified

1. **[rough_env_cfg.py](source/isaaclab_tasks/isaaclab_tasks/manager_based/locomotion/velocity/config/humanoid_snc_r5/rough_env_cfg.py)** (MODIFIED)
   - Changed `actions.joint_pos.scale` from float to dictionary
   - Applied -0.5 scale to `left_hip_pitch_joint` (inverted)
   - Applied +0.5 scale to all other joints (normal)

### How It Works

Isaac Lab's `JointAction` class supports per-joint scaling using a dictionary:

```python
# Configuration in rough_env_cfg.py
self.actions.joint_pos.scale = {
    ".*": 0.5,                      # Default scale for all joints
    "left_hip_pitch_joint": -0.5,   # NEGATIVE scale inverts the action
}

# When policy outputs symmetric actions:
policy_action = [0.3, 0.3]  # Same value for left and right hip

# Isaac Lab applies the scales:
left_hip_action  = 0.3 × (-0.5) = -0.15  # Inverted
right_hip_action = 0.3 × (+0.5) = +0.15  # Normal

# Result: Both legs step FORWARD symmetrically ✓
```

## Technical Notes

### Why Use Action Scale Dictionary?

The action scale dictionary approach is superior because:
1. ✓ Uses built-in Isaac Lab feature (no custom code)
2. ✓ No need to regenerate USD files
3. ✓ Works immediately without Isaac Sim re-processing
4. ✓ Simple and clean configuration
5. ✓ Easy to debug and verify
6. ✓ Can be easily removed if URDF is fixed later

### Future Improvements

If you want to permanently fix the URDF:
1. Fix the left_hip_pitch_joint axis in the URDF to match right hip
2. Regenerate the USD file using Isaac Sim URDF importer
3. Change action scale back to simple float: `self.actions.joint_pos.scale = 0.5`
4. Retrain the model
